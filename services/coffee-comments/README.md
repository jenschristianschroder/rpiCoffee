# Coffee Brew Comments

An offline comment service for black coffee, cappuccino, espresso, and `other`
machine activity. Its source, phrase model, and tests are included in this
repository. No second checkout, separately published service image, or model download is required.
It combines weighted authored phrases and sentence structures; it is not a neural LLM.

## Large and classic models

Version 2 defaults to the **large** model. The generation endpoints, service name,
port, and pipeline mappings are unchanged. Updating an existing installation
therefore selects the larger model without re-registering or rewiring the service.

| Model data | Classic | Large |
| --- | ---: | ---: |
| File size | 93,489 bytes (93.5 KB) | 569,347 bytes (569.3 KB) |
| Complete punchlines | 420 | 1,000 |
| Opening styles | 20 | 60 |
| Sentence families | 0 | 100 |
| Sentence patterns | 0 | 400 (four introductions per family) |
| Typed phrase fragments | 0 | 2,000 |
| Sampling weights | 440 | 3,460 |
| Learned neural parameters | 0 | 0 |

The large bank contains 750 coffee jokes and 250 mystery-event jokes. It retains
every original joke and adds weekday-specific material, selected using the event's
date in the configured timezone. Its 20 vocabulary banks each combine five compatible
modifiers with 20 base phrases. These are lexical variations, not 2,000 new jokes.
Patterns compose those fragments into sentences alongside the complete joke bank.
Comments are checked to stay within 220 characters for all shipped combinations.

For a fixed coffee, weekday, and time period, the large model permits roughly
28.8–62.4 million selectable combinations. This is a combinatorial count, **not**
a count of distinct jokes or a claim of general language ability. All four versions
of a sentence family share a repetition key, so changing its introduction does not
allow the same premise to bypass recent-history protection.

Select **classic** or **large** in **Admin → Service Settings → coffee-comments →
Model variant**, then save. The change applies immediately and survives restarts.
`COFFEE_MODEL_VARIANT` in the root `.env` sets the initial default only; after a
selection is saved through settings, the saved value takes precedence.
The original `weights.json` remains unchanged. Model files exclude the Python
runtime, Docker image, and history database.

Check the active model, exact size, counts, and combination range without generating
a comment:

```bash
curl -sS http://127.0.0.1:8004/model
```

## Update the Pi

From your existing rpiCoffee checkout:

```bash
git pull
sudo reboot
```

The systemd unit generated by `setup.sh` already runs Docker Compose with
`up -d --build --force-recreate`. The new `coffee-comments` service has no Compose
profile, so that existing command builds it from this directory and starts it
alongside the enabled services. The first build downloads the Python base image
and packages; comment generation runs offline afterward. You do not need to run
`setup.sh` again for this addition.

The host endpoint is **http://127.0.0.1:8004**. Port 8004 is distinct from the
app (8080), classifier (8001), llama-cpp (8002), Ollama proxy (8003), raw Ollama
(8000), TTS (5050), and remote-save (7000) defaults. Docker maps host port 8004
to port 8080 inside this container. The loopback binding lets the native app
reach it without exposing a separate service port on the LAN.

## Register and wire it yourself

The upgrade does not register the service or modify your saved pipeline.

1. In the admin dashboard's Service Registry, register the name
   **`coffee-comments`** with endpoint **`http://127.0.0.1:8004`**.
   Registration fetches `/manifest`. Check that the service is healthy.
2. Open the pipeline editor and replace the existing generation node with
   `coffee-comments`. Keep the existing LLM registrations so you can use them again.
3. Connect these inputs and outputs:

| Input | Source |
|---|---|
| `coffee-comments.coffee_label` | `$classifier.label` |
| `coffee-comments.timestamp` | `$sensor.timestamp` |
| `tts.text` | `$coffee-comments.response` |
| `remote-save.text` | `$coffee-comments.response` |

Keep the classifier, sensor, and other remote-save connections, then save the
pipeline and run a test brew. Use exactly `coffee-comments` as the registration
name so the kiosk emits its text event and includes the comment in the result.
Use one generation node per brew. The pipeline editor controls which provider is
called; the container can stay running while another provider is selected.

## API

```bash
curl -sS http://127.0.0.1:8004/health
curl -sS http://127.0.0.1:8004/manifest
curl -sS http://127.0.0.1:8004/generate \
  -H 'Content-Type: application/json' \
  -d '{"coffee_label":"espresso","timestamp":"2026-11-05T09:30:00+01:00"}'
```

`POST /generate` returns `{"response":"...","elapsed_s":0.002}` (the measured
duration varies). Send only `coffee_label` and `timestamp`. Dates must include
`Z` or an explicit UTC offset. The `unknown`, `unrecognized`, and `unrecognised`
aliases use the `other` mystery-event material; unsupported drinks and extra
fields return HTTP 422. Prompt and token settings do not apply to this service.

The original `POST /comment` API accepts `coffee_type` and `datetime` and returns
`{"comment":"..."}`. Both APIs share the same persistent repetition history.
`GET /coffee-types` lists supported types and the timezone; `/docs` describes
both APIs. Each successful request generates a new comment, without event
deduplication or audio playback.

## Settings and history

If `coffee-comments` was already registered before this upgrade, click its
**Refresh manifest** button (circular arrow) in the **Service Registry** once.
The app caches registered manifests; refreshing exposes the new **Service Settings**
panel without changing your pipeline. Newly registered services discover it automatically.

The manifest advertises `GET /settings` and `PATCH /settings`. You can also switch
models directly on the Pi:

```bash
curl -sS http://127.0.0.1:8004/settings
curl -sS -X PATCH http://127.0.0.1:8004/settings \
  -H 'Content-Type: application/json' \
  -d '{"settings":{"COFFEE_MODEL_VARIANT":"classic"}}'
```

Use `large` to switch back. Flat `{"COFFEE_MODEL_VARIANT":"large"}` bodies are
also accepted. Invalid values or unknown keys return 422. Updates are validated
and saved atomically before changing the running model; a failed update keeps the
previous selection. Both generation APIs switch together and retain history.
The Docker service uses one worker to keep runtime selection consistent.

The selection is stored in `/data/settings.json` beside the history database.
Startup precedence is: an explicit `WEIGHTS_PATH` override, saved selection,
`COFFEE_MODEL_VARIANT`, then `large`. When custom weights are explicitly supplied,
the selector is read-only and displays `custom`; remove that override and restart
to use the bundled selector. Other service configuration remains in the environment.

Compose defaults to `COFFEE_TIMEZONE=Europe/Copenhagen`. To change the timezone
or host port, set `COFFEE_TIMEZONE` or `COFFEE_COMMENTS_PORT` in the root `.env`
and recreate the container or reboot. If changing the port, also update its
registry endpoint and `COFFEE_COMMENTS_ENDPOINT` for the start/status scripts.

The named volume `coffee-comments-data` stores the selection and `/data/history.sqlite3`, retaining
the recent joke/opening history and usage counters across updates and reboots.
The large model also balances fragment usage; those counters persist in the same
database. It avoids the last 60 joke premises and the last two opening styles.
Switching models retains history, and the existing database is upgraded in place.
Do not remove that volume when updating if you want to retain repetition history.
To edit the classic humor, update `phrases.py` and run `python write_weights.py`.
The large model adds `large_phrases.py` and `large_grammar.py`; regenerate it with
`python write_large_weights.py` after editing any of those sources, then rebuild.
Keep existing joke IDs stable by appending within groups. The builder verifies
group counts; intentionally expanding a group requires updating its expected count.

## Development

From the repository root:

```bash
docker build --target test -t rpicoffee-comments-test services/coffee-comments
docker run --rm rpicoffee-comments-test
docker compose up -d --build coffee-comments
BASE_URL=http://127.0.0.1:8004 python services/coffee-comments/tests/smoke_http.py
```

The model/API suite runs in the service's isolated test image and covers both variants.
The app's pytest suite additionally checks manifest registration, pipeline text
events, TTS/remote-save wiring, and the final kiosk result. CI tests this Docker
service on ARM64 and x86-64, switches between models using the same history volume,
and checks the solution's default host ports.
