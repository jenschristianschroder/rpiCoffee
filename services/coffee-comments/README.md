# Coffee Brew Comments

An offline comment service for black coffee, cappuccino, espresso, and `other`
machine activity. Its source, phrase model, and tests are included in this
repository. No second checkout, separately published service image, or model download is required.
It combines weighted authored phrases; it is not a neural LLM.

## Update the Pi

From your existing rpiCoffee checkout:

```bash
git pull
sudo reboot
```

The systemd unit generated by `setup.sh` already runs Docker Compose with
`up -d --build --force-recreate`. The new `coffee-comments` service has no Compose
profile, so that existing command builds it from this directory and starts it
alongside the enabled services. The first build downloads the Python base image
and packages; comment generation runs offline afterward. You do not need to run
`setup.sh` again for this addition.

The host endpoint is **http://127.0.0.1:8004**. Port 8004 is distinct from the
app (8080), classifier (8001), llama-cpp (8002), Ollama proxy (8003), raw Ollama
(8000), TTS (5050), and remote-save (7000) defaults. Docker maps host port 8004
to port 8080 inside this container. The loopback binding lets the native app
reach it without exposing a separate service port on the LAN.

## Register and wire it yourself

The upgrade does not register the service or modify your saved pipeline.

1. In the admin dashboard's Service Registry, register the name
   **`coffee-comments`** with endpoint **`http://127.0.0.1:8004`**.
   Registration fetches `/manifest`. Check that the service is healthy.
2. Open the pipeline editor and replace the existing generation node with
   `coffee-comments`. Keep the existing LLM registrations so you can use them again.
3. Connect these inputs and outputs:

| Input | Source |
|---|---|
| `coffee-comments.coffee_label` | `$classifier.label` |
| `coffee-comments.timestamp` | `$sensor.timestamp` |
| `tts.text` | `$coffee-comments.response` |
| `remote-save.text` | `$coffee-comments.response` |

Keep the classifier, sensor, and other remote-save connections, then save the
pipeline and run a test brew. Use exactly `coffee-comments` as the registration
name so the kiosk emits its text event and includes the comment in the result.
Use one generation node per brew. The pipeline editor controls which provider is
called; the container can stay running while another provider is selected.

## API

```bash
curl -sS http://127.0.0.1:8004/health
curl -sS http://127.0.0.1:8004/manifest
curl -sS http://127.0.0.1:8004/generate \
  -H 'Content-Type: application/json' \
  -d '{"coffee_label":"espresso","timestamp":"2026-11-05T09:30:00+01:00"}'
```

`POST /generate` returns `{"response":"...","elapsed_s":0.002}` (the measured
duration varies). Send only `coffee_label` and `timestamp`. Dates must include
`Z` or an explicit UTC offset. The `unknown`, `unrecognized`, and `unrecognised`
aliases use the `other` mystery-event material; unsupported drinks and extra
fields return HTTP 422. Prompt and token settings do not apply to this service.

The original `POST /comment` API accepts `coffee_type` and `datetime` and returns
`{"comment":"..."}`. Both APIs share the same persistent repetition history.
`GET /coffee-types` lists supported types and the timezone; `/docs` describes
both APIs. Each successful request generates a new comment, without event
deduplication or audio playback.

## Settings and history

Compose defaults to `COFFEE_TIMEZONE=Europe/Copenhagen`. To change the timezone
or host port, set `COFFEE_TIMEZONE` or `COFFEE_COMMENTS_PORT` in the root `.env`
and recreate the container or reboot. If changing the port, also update its
registry endpoint and `COFFEE_COMMENTS_ENDPOINT` for the start/status scripts.

The named volume `coffee-comments-data` stores `/data/history.sqlite3`, retaining
the recent joke/opening history and usage counters across updates and reboots.
Do not remove that volume when updating if you want to retain repetition history.
To edit the humor, update `phrases.py`, run `python write_weights.py` in this
directory, and rebuild. Keep existing joke IDs stable.

## Development

From the repository root:

```bash
docker build --target test -t rpicoffee-comments-test services/coffee-comments
docker run --rm rpicoffee-comments-test
docker compose up -d --build coffee-comments
BASE_URL=http://127.0.0.1:8004 python services/coffee-comments/tests/smoke_http.py
```

The preserved upstream model/API suite runs in the service's isolated test image.
The app's pytest suite additionally checks manifest registration, pipeline text
events, TTS/remote-save wiring, and the final kiosk result. CI tests this Docker
service on ARM64 and x86-64 and checks the solution's default host ports.
